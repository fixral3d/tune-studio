# VEMS V3 ECU simulator — Waveshare ESP32-S3-Touch-LCD-2.1

A hardware ECU simulator: the board shows up on USB as **"VEMS V3 Simulator"** (VID 303A, PID 81B3) and speaks the
V3 TriggerFrame protocol. Real VemsTune 1.5.46 and the VEMS Tuner app connect to it like a real ECU.
- The touch screen drives an engine model: throttle, key, coolant, intake air, battery.
- `.hex` / `.uhex` firmware can be uploaded through the emulated bootloader.

Verified on 2026-11-01:
- **VemsTune:** "ECU (v3) connected" → reads all pages + EEPROM → Online, fw 1.2.34, RT flow 27 Hz, live gauges.
- **Uploads:** `flash.mjs` writes and verifies a `.hex` and a `.uhex` (392 pages each, "firmware is identical").

## What it emulates
Same behaviour as `packages/core/src/emulator/ecu.ts` + `bootloader.ts`, ported to C++ (`src/ecu.cpp`).

| Message | Behaviour |
|---|---|
| `F2` details | serial `v3.3_n001453` (`_u…` when boot type is UHEX), fw 1.2.34 signature |
| `A0` realtime | 80-byte block from the engine model (`src/engine.cpp`, port of the demo engine in `apps/tuner/src/lib/device.ts`) |
| `F4` / `FB` / `EF` | pages read / write / burn |
| `F5` | EEPROM |
| `F7` TEST_TOOLS | ENA_FLAGS `02`/`03` → WBO2 free-air calibration (O2 % in `pulseWidth_raw`); `40` → trigger-log stream |
| `F6` | bootloader: `S`, `e`, `A`, `Dkk`/`Dcc`, `Dll`/`DCC`, marker, `E` |

Notes on storage and state:
- **Burned pages:** kept in LittleFS (`/pages.bin`).
- **Uploaded firmware:** kept in `/firmware.bin`.
- **Seed:** the pages start from VemsTune's own `defaultfirmwareconfigs/config_1.2.34.vemscfg` (`src/seed_pages.h`,
  generated by `node tools/gen_seed.mjs`). `prohibit_h/l` is set to the 1.2.34 code, so VemsTune does not report
  "Safe Mode". When the seed changes, the burned pages are replaced (`SEED_HASH`).
- **Trigger log:** a 36-1 wheel with a cam pulse every 720° and 2 sparks per revolution, at the engine model's rpm.

## Touch screen (swipe left/right)
1. **Motor:** the outer ring is the throttle (drag it). The middle shows RPM, MAP, lambda, coolant and battery.
   KONTAK/STOP turns the key, and turning it on cranks for 1.5 s first.
2. **Sensörler:** coolant, intake air and battery sliders, plus *Otomatik sürüş*. Auto drive runs the demo cycle
   (900–6500 rpm, 28–100 kPa) so the VE analysers have data.
3. **ECU:**
   - PC link and counters (frames, writes, burns, firmware pages, unburned state).
   - Current mode: WBO2 calibration, trigger log, or bootloader.
   - **Boot tipi HEX/UHEX:** sets the serial letter, which decides the firmware file type VemsTune offers.
   - **Fabrika config:** reloads the seed.
   - **Flash modu:** reboots into the ROM bootloader.

## Build / flash
Requirements: PlatformIO (pioarduino platform 53.03.13 = Arduino-ESP32 3.x) and LVGL 8.3.10.
```
pwsh tools/flash.ps1        # build → 1200-baud touch → esptool on the ROM port → simulator back
```
- First flash, or a board that does not answer: hold **BOOT**, tap **RESET**, release BOOT. Then run
  `pio run -t upload --upload-port <ROM COM port>`.
- If Windows still shows the old JTAG device after flashing, replug the USB cable once.

## Ports
- **ECU port (e.g. COM12):** the only port by default. Use it in VemsTune / the app, at any baud rate.
- **Debug trace port (opt-in):** build with `-DSIM_DEBUG_PORT` (add it to `build_flags`) for a second port, MI_02
  (e.g. COM13), that shows what the host sends and what the simulator answers. It is off by default, because two
  identically named ports confuse port pickers.
  ```
  cp tools/trace.mjs ../../apps/emu-cli/trace.tmp.mjs; node ../../apps/emu-cli/trace.tmp.mjs COM13
  ```

## USB findings (why the code looks like it does)
- **Native USB-Serial/JTAG mode:** VemsTune's DTR/RTS toggling put the chip into ROM download mode.
  The fix is TinyUSB CDC with reboot detection off.
- **Writes while DTR is low:** Arduino `USBCDC::write` sends nothing while DTR is low, so writes go to
  `tud_cdc_n_write` directly.
- **Large answers:** an answer sent as whole 64-byte packets (a 261-byte page) was not handed to VemsTune until more
  data came, so VemsTune timed out and re-probed. Transfers of ≤ 63 bytes (always a short packet) fixed it.
- **DSR:** VemsTune works over USB without DSR. A SERIAL_STATE notification was never polled by usbser.sys, and
  that code was removed.
- **Re-enumeration:** after an esptool reset Windows kept the stale JTAG device. Dropping the D+ pull-up for
  500 ms at boot makes it re-enumerate.

## Files
- `src/main.cpp`: USB.
- `src/ecu.*`: protocol, bootloader, trigger log, storage.
- `src/engine.*`: engine model.
- `src/ui.cpp`: LVGL screen, running on core 0.
- `src/board/*`: Waveshare demo drivers (ST7701, CST820, TCA9554).
- `tools/`: seed generator, flash script, 1200-baud touch, trace reader.
